# Proposal: 审核模式开关

## 问题陈述

应用当前没有运营管控手段。当平台需要对内容进行审核管控时，无法从客户端侧隐藏敏感页面（首页、消息 tab），导致审核期间用户仍可访问这些功能。

## 目标

- 通过服务端配置控制客户端是否进入"审核模式"
- 审核模式下自动隐藏首页/消息 tab，重定向用户到日记页面
- 审核模式下跳过未读消息拉取，避免请求受保护接口
- 配置拉取失败时优雅降级为正常模式，保证应用可用性

## 非目标

- 不提供客户端手动切换审核模式的入口
- 不实现服务端侧的内容审核逻辑
- 不做实时推送的审核状态变更（仅启动时拉取）

## 技术方案概述

在启动时拉取全局配置中的 `auditMode` 布尔值，存入 zustand store。App 入口根据该值决定：
1. 是否加载未读消息
2. 是否重定向到日记 tab
3. Tab bar 自定义组件根据 auditMode 过滤要显示的 tab

## 验收标准

- [ ] 服务端返回 `auditMode: true` 时，首页和消息 tab 不显示
- [ ] 服务端返回 `auditMode: false` 或配置拉取失败时，正常显示所有 tab
- [ ] 审核模式下启动不请求未读消息接口
- [ ] 审核模式下自动跳转到日记 tab
- [ ] 新增 zustand store（audit.ts）管理审核模式状态
- [ ] 新增 API 配置端点（appConfig.ts）
- [ ] 单元测试覆盖 audit store 逻辑
